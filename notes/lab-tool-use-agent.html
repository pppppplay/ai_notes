學生生活小管家：Tool Use Agent

做一個會自己選工具的 Agent，幫大學生算 GPA、倒數考試天數、分帳和推薦午餐，用 Gradio 展示。

做了什麼

大學生常問的問題需要精確計算或知道今天日期，直接問 LLM 容易錯，所以準備了六個工具：

工具功能
calculator計算數學式
get_today取得今天日期
days_until計算距離某天還有幾天
gpa_calculator百分制成績換算 4.3 制 GPA
pick_lunch依預算推薦午餐
wiki_search查中文維基百科

使用的技術：Groq 的 gpt-oss-120b（透過 AISuite 呼叫）、Gradio、Google Colab。

怎麼運作

  1. 把工具的名稱和參數說明寫進 system prompt
  2. LLM 每一步輸出一個 JSON，例如 {"action": "calculator", "action_input": {"expression": "3480/5"}}
  3. 程式執行對應的函式，結果用 Observation 傳回給 LLM
  4. LLM 決定要再用工具，還是輸出 final_answer
  5. 最多重複 6 步，避免無限迴圈

因為是迴圈，可以連續使用多個工具。「離期末考還有幾天、每天要讀幾章」會依序用 get_today → days_until → calculator。

例子：有工具 vs 沒工具

問「3.7 的 2.9 次方乘以根號 77，算到小數點後 6 位」：

直接問 LLM：390.307945
Agent 用 calculator：389.969249（正確）

遇到的問題

問題原因怎麼解決
429 Rate limitGroq 免費帳號每分鐘有 token 上限從錯誤訊息讀出要等幾秒，自動等待後重試
400 tool_use_failed模型改用內建的 function calling 格式輸出，被 API 擋下從錯誤內容取出模型選的工具和參數，轉回自己的 JSON 格式繼續執行
沒用工具就回答 GPA 3.27（正確是 3.80）格式錯誤後，模型直接編了一個答案還沒用過工具就想回答時，程式會先要求確認一次
容易搞錯

看到 Agent 回答得很流暢，不代表它真的有用工具。要看執行過程有沒有工具紀錄，所以 Gradio 介面右邊另外顯示每一步用了什麼工具、得到什麼結果。

我的想法

原本以為接上工具就結束了，實際跑起來才發現大部分時間都在處理模型「不照格式輸出」的狀況。錯誤處理寫得越完整，Agent 才越可靠。
